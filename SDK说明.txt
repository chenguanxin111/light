Mars-SDK说明
SDK简介
什么是 Mars SDK？
Mars SDK 是一个用于开发智能语音交互设备的软件开发套件（SDK）。它基于 RISC-V 架构芯片（CSK系列），提供了完整的语音识别、命令词检测、提示音播放等功能。

主要特点：

支持离线语音识别，无需联网
支持自定义命令词和协议
提供丰富的硬件驱动接口（GPIO、UART、PWM、I2C等）
集成实时操作系统（RTOS）支持
跨平台编译支持（Windows 和 Linux）
自动化工具链下载和配置
适用场景：

智能家电（灯具、窗帘、风扇等）
智能音箱
儿童玩具
车载语音助手
其他需要语音交互的嵌入式设备

各目录详细说明
1. chip/ - 芯片相关目录
这个目录包含芯片级别的底层代码，包括硬件驱动和板级支持包（BSP）。

chip/

│   ├── Driver_GPIO.h      # GPIO驱动接口
│   ├── Driver_UART.h      # UART串口驱动
│   ├── Driver_I2C.h       # I2C驱动接口
│   ├── Driver_SPI.h       # SPI驱动接口
│   ├── Driver_GPT_PWM.h   # PWM脉宽调制驱动
│   ├── Driver_ADC_PDM.h   # ADC音频采集驱动
│   ├── Driver_CLASSD.h    # Class D功放驱动
│   ├── ClockManager.h     # 时钟管理
│   └── IOMuxManager.h     # IO引脚复用管理
│
├── bsp/               # 板级支持包（Board Support Package）
│   └── system_RISCVN300.h # 系统初始化配置
│
└── rom/               # ROM相关文件（芯片固化的代码）
开发提示：

✅ 你需要了解这个目录的内容，但通常不需要修改它
✅ 使用 chip/include/ 下的驱动头文件来操作硬件
✅ BSP 文件定义了芯片的基础配置（时钟、中断等）

⚠️ 重要说明：

✅ 重点开发内容：外设初始化、GPIO控制（A10、A11、A12、B11）、业务逻辑
❌ 无需关注：命令词、提示音配置（由网页平台自动生成）
❌ 无需修改：ls_app_cfg_user.h、tone.h、tone_buf.h（平台自动更新）
⚠️ 关于 mods 文件夹的特殊说明：

source/mods/ 文件夹中的代码与普通示例代码不同，它们有以下特点：

自动执行机制：
mods 中的模块会在系统启动时自动初始化和执行
例如：mod_xwdt.c 会在启动时自动初始化看门狗（如果 CONFIG_XWDT_ENABLE=1）
这意味着它们不是供学习使用的示例代码，而是实际运行的系统模块
宏配置控制：
每个模块都有对应的宏配置，在 include/autoconf.h 中定义
例如：
#define CONFIG_XWDT_ENABLE 1      // 启用看门狗模块
#define CONFIG_AADC_ENABLE 1      // 启用音频ADC模块
#define CONFIG_CLSD_ENABLE 1      // 启用Class D功放模块
如何修改外设配置： 如果你需要修改某个外设的默认配置（例如修改看门狗的超时时间），有两种方法： 方法1：禁用默认模块，自己实现（推荐）⭐
// 1. 在 include/autoconf.h 中禁用默认模块
// #define CONFIG_XWDT_ENABLE 1
#define CONFIG_XWDT_ENABLE 0   // 禁用默认看门狗模块

// 2. 在 main.c 或其他地方自己实现看门狗配置
// 参考 source/listen/app/ls_app_wdt.c 中的示例
void my_wdt_init() {
    // 自定义看门狗配置
    AON_WDT_Initialize(AON_WDT(), NULL, NULL);
    AON_WDT_Control(AON_WDT(), HAL_AON_WDT_TIME_Msk, 320000);  // 自定义超时时间
    // ...
}
方法2：直接修改 mods 模块代码
// 直接修改 source/mods/mod_xwdt.c 中的配置
// 例如修改第4行的超时时间
#define WDT_TIMER_PERIOD (64000)  // 改为你需要的值

// 但注意：这种方法在SDK更新时可能会被覆盖
常见配置冲突问题： 如果你在 main.c 中配置了某个外设，但发现配置不生效，可能是因为对应的 mods 模块已经自动执行了。 解决方案：
检查 include/autoconf.h，确认是否有对应的 CONFIG_XXX_ENABLE 宏
如果有，将其设置为 0 来禁用默认模块
然后在你的代码中实现自定义配置
示例：看门狗配置冲突
// 问题：你在 main.c 中配置看门狗，但发现不生效

// 原因：mod_xwdt.c 已经自动初始化了看门狗

// 解决方案：
// 1. 在 include/autoconf.h 第88行
#define CONFIG_XWDT_ENABLE 0   // 禁用默认看门狗模块

// 2. 在 main.c 中自己配置看门狗
extern int wdt_init_reset_mode();
wdt_init_reset_mode();

✅ 开发重点：GPIO引脚控制（A10、B11），实现具体的硬件控制逻辑
2. SDK架构概览
Mars SDK 采用分层架构：

┌─────────────────────────────────────┐
│  应用层 (source/listen/app/)         │  ← 你的开发重点⭐⭐⭐

├─────────────────────────────────────┤
│  配置层（平台自动生成，无需修改）      │  ← 网页平台配置
│  - 命令词定义                        │
│  - 提示音数据                        │
│  - 协议格式                          │
├─────────────────────────────────────┤
│  服务层 (source/listen/)             │
│  - 音频播放（已配置）                │
│  - 语音识别回调（已配置）            │
│  - 资源管理                          │
├─────────────────────────────────────┤
│  硬件抽象层 (source/mods/)           │  ← GPIO驱动实现
│  - GPIO驱动                          │
│  - UART驱动                          │
│  - PWM驱动                           │
├─────────────────────────────────────┤
